Implement a last-in-first-out (LIFO) stack using only two queues.  Assume that `top` and `pop` will never be called on an empty stack.

## Solution

??? "Expand"

    $O(n)$ push and $O(1)$ pop.

    We can simply `enqueue` the incoming element in the underlying queue. If it was originally sized $n$, then now its size is $n-1$.

    Now we move the $n$ elements from the front to the back.

    ```kotlin
    class MyStack() {

      private val queue = ArrayDeque<Int>()

      fun push(x: Int) {
        queue.addLast(x)
        for (i in 1 until queue.size) {
          queue.addLast(queue.removeFirst())
        }
      }

      fun pop(): Int = queue.removeFirst()

      fun top(): Int = queue.first()

      fun empty(): Boolean = queue.isEmpty()

    }
    ```

    | Before | Action | After |
    |--------|--------|-------|
    | `[]`   | `push(1) ` | `[1]` | 
    | `[1]`   | `push(2) ` | `[1, 2]` |    
    |         |            | `[2, 1]` |   
    | `[2, 1]`   | `push(3) ` | `[2, 1, 3]` |    
    |            |            | `[3, 2, 1]` |  
    | `[3, 2, 1]`   | `pop()` | `[2, 1]` |    


    In the Queue-using-Stacks version, the "move" operation reverses the order of elements, which is exactly what you need to turn LIFO into FIFO. Once moved, the elements stay in the correct order for multiple $O(1)$ pops.
    
    In a Stack-using-Queues version, there is no way to "set it and forget it." To maintain the LIFO property using FIFO structures, at least one operation must fundamentally reorganize the data on every call or every cycle.
